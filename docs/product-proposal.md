# Steerloop 产品方案（初稿）

> 文档状态：初稿  
> 更新日期：2026-08-21

## 一、项目结论

这个需求真实存在，但产品不能只定位为“把 Codex 会话同步到手机”。

截至目前，OpenAI 已经推出 ChatGPT Remote，能够连接 Mac 或 Windows 电脑，在手机上启动任务、查看进度、批准操作、发送指令和审阅代码。因此，如果只复制这些能力，产品差异化和长期生存空间会比较有限。[OpenAI Remote 官方说明](https://learn.chatgpt.com/docs/remote)

更切实可行的定位是：

> Steerloop 是一个本地优先、可自托管、面向多台电脑和 Linux 服务器的 AI Agent 远程控制中心。  
> 用户可以在手机上查看任务进度、处理阻塞、批准敏感操作和审阅结果，而代码与命令始终在用户自己的机器上执行。

第一阶段只支持 Codex，把体验做通；产品架构从一开始保留多 Agent 适配能力，未来再接入其他编程 Agent、训练任务、CI 和运维任务。

---

## 二、产品定位

### 一句话定位

> 离开电脑，任务继续；需要你时，手机提醒。

### 核心价值

Steerloop 不把手机变成一个缩小版终端，而是把手机变成 AI 工程任务的“控制台”。

用户在手机上只需要完成四类高价值操作：

- 看：现在进行到哪里，有没有卡住
- 批：是否允许执行某个命令、联网或访问工作区之外的文件
- 答：回复 Agent 的澄清问题或补充约束
- 验：查看修改摘要、测试结果和代码差异

### 首批目标用户

- 经常让 Codex 运行十几分钟到数小时任务的开发者
- 使用 Linux 服务器、GPU 工作站、云主机或远程开发机的用户
- 同时管理多台机器、多个项目和多个 Agent 会话的工程师
- 对代码隐私、自托管和权限审计有要求的个人或团队

---

## 三、明确不做什么

第一阶段不做：

- 完整远程终端
- 手机代码编辑器
- SSH 客户端
- 远程桌面
- 云端开发环境
- 任意命令执行入口
- 自动批准所有权限

这样可以显著缩小开发范围和安全攻击面。

Steerloop 传输的是结构化任务事件和有限控制指令，而不是把整个 Shell 暴露给手机。

---

## 四、核心使用流程

1. 用户在电脑或服务器安装 `brainwaves-agent`。
2. Agent 显示二维码，用户用手机完成设备绑定。
3. 用户通过 Steerloop 启动或恢复 Codex 会话。
4. 任务继续在原电脑或服务器上运行。
5. 手机显示任务状态：
   - 正在分析
   - 正在修改
   - 正在运行测试
   - 等待权限
   - 等待回复
   - 已完成
   - 失败或设备离线
6. Codex 请求敏感权限时，手机收到推送。
7. 用户查看完整命令、工作目录、风险说明和授权范围。
8. 用户选择“仅允许本次”或“拒绝并回复”。
9. 任务完成后，手机展示修改摘要、测试结果和 diff。
10. 用户决定继续修改、重新测试或结束任务。

## 五、MVP 功能范围

### 1. 设备与会话

- 二维码绑定手机和主机
- 支持一名用户绑定多台主机
- 展示主机在线、离线和最后心跳时间
- 展示 Codex 会话列表
- 启动、恢复和查看会话
- 展示会话当前状态和最近事件

### 2. 进度查看

不直接堆砌终端日志，而是显示结构化时间线：

- Codex 正在做什么
- 最近修改了哪些文件
- 当前运行的测试或命令
- 已持续多长时间
- 是否需要用户介入
- 最后一次有效活动时间

同时保留“展开原始输出”，供需要排查问题的高级用户使用。

### 3. 权限审批

每个审批卡片必须展示：

- 完整命令或操作
- 执行机器
- 项目和工作目录
- 请求原因
- 涉及网络、文件或外部系统的范围
- Codex 给出的风险说明
- 授权有效期

MVP 只提供：

- 仅允许本次
- 拒绝
- 拒绝并要求使用更安全的方法

“始终允许”和批量自动审批放到后续版本。

### 4. 远程干预

- 回复 Codex 的问题
- 补充任务约束
- 排队发送下一条指令
- 中止当前任务

第一阶段不提供任意 Shell 输入。

### 5. 完成与异常通知

- 等待权限
- 等待用户回答
- 任务完成
- 任务失败
- 主机掉线
- 长时间没有有效进展

## 六、技术实现方案

Codex 官方提供 App Server 协议，能够提供会话历史、审批、身份认证和流式 Agent 事件，并支持列出、读取、恢复会话以及启动、引导和中断任务。这意味着不需要通过不稳定的终端文字抓取来实现核心能力。[Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)

建议架构如下：

```text
Codex App Server
      │ 本机 stdio / Unix Socket
      ▼
brainwaves-agent
      │ 主动建立加密出站连接
      ▼
Steerloop Relay
      │ 路由事件、推送通知
      ▼
手机 PWA / App
```

### 主机端 Agent

负责：

- 启动和管理 Codex App Server
- 将 Codex 事件转换成统一事件格式
- 保存本地会话状态
- 执行最终权限校验
- 与云端中继建立出站连接
- 断线后补发缺失事件

不需要在服务器上开放入站端口。

### 中继服务

只负责：

- 用户与设备身份认证
- 连接路由
- 离线消息
- 推送通知
- 加密事件暂存

理想情况下，中继服务只保存密文，无法读取代码、命令正文和会话内容。

### 手机端

第一阶段使用响应式 Web/PWA，降低开发成本；验证需求后再开发原生应用，以获得更可靠的推送、生物识别和设备密钥保护。

### 重要技术边界

Codex App Server 的直接 WebSocket 传输目前仍被官方标记为实验性、不建议直接用于生产。因此 Steerloop 不应把它暴露到公网，而应通过主机端 Agent 使用本地 stdio 或 Unix Socket，再建立自己的加密出站连接。[Codex App Server 安全说明](https://learn.chatgpt.com/docs/app-server)

## 七、安全设计

安全不是附加功能，而是这个产品是否成立的前提。

### 基本原则

- 默认只读
- 不开放远程 Shell
- 不直接暴露 Codex App Server
- 不把 API Key 和环境变量上传到中继服务
- 主机端始终拥有最终拒绝权
- 每次授权只对应一个确定的操作

### 防止审批被替换

手机批准的不是一段普通文本，而是经过签名的审批对象，至少包含：

- 会话 ID
- 审批请求 ID
- 规范化命令的哈希
- 工作目录
- 权限范围
- 有效时间
- 随机数
- 手机设备签名

即使中继服务被攻击，也不能把“批准运行测试”替换成“批准删除文件”。

### 授权等级

后续可以逐步扩展为：

- 仅本次
- 当前会话内允许相同操作
- 当前项目内允许指定命令前缀
- 团队管理员预设策略

Codex 本身已经采用沙箱与审批策略双层控制：沙箱决定技术上可以做什么，审批策略决定何时必须向用户确认。Steerloop 应保留这套边界，而不是绕过它。[Codex 审批与安全文档](https://learn.chatgpt.com/docs/agent-approvals-security)

## 八、分阶段推进路线

| 阶段 | 目标 | 主要交付 |
| --- | --- | --- |
| 概念验证，1–2 周 | 证明技术链路可行 | 单机 Codex 事件同步、会话状态、一次性权限审批、简单手机页面 |
| 私测版，4–6 周 | 完成端到端使用闭环 | QR 绑定、跨网络连接、推送、断线恢复、回复与中止、完成摘要 |
| 公测版，2–3 个月 | 支持真实长期使用 | 多主机、会话搜索、diff、测试结果、Linux 服务化部署、自托管中继 |
| 扩展版，3–6 个月 | 从 Codex 工具变成 Agent 控制层 | 多 Agent 适配、统一任务协议、策略模板、资源监控 |
| 团队版 | 建立商业能力 | SSO、RBAC、审批委托、审计日志、组织策略和私有化部署 |

多 Agent 接入应采用能力分级：

- Level 1：只能查看状态和日志
- Level 2：可以回复和中止
- Level 3：支持结构化权限审批
- Level 4：支持 diff、任务恢复和完整生命周期

这样不会因为其他 Agent 缺少某项接口而阻塞整个产品扩展。

## 九、第一阶段验收标准

MVP 必须满足：

- 手机使用移动网络，服务器处于 NAT 后仍可连接
- 不开放服务器入站端口
- 手机可以看到任务运行、等待审批、完成和失败状态
- 审批与具体命令、目录和会话严格绑定
- 网络断开后可以恢复，不重复执行审批
- 手机关闭不影响服务器任务继续运行
- 中继服务不能直接执行主机命令
- 主机离线时手机能够明确显示，而不是一直显示“运行中”
- 从权限请求发出到手机收到通知，正常情况下不超过数秒

初期最重要的产品指标不是注册量，而是：

> Steerloop 每周为用户减少了多少“任务等待人工确认”的时间。

## 十、主要风险与应对

### 官方产品竞争

OpenAI Remote 已覆盖 Codex 手机远程控制。

应对方式：重点服务 Linux 服务器、自托管、跨 Agent、多主机、团队审批和审计，不把产品绑定在“Codex 手机客户端”这一条价值上。

### Codex 协议变化

App Server 部分能力仍在演进。

应对方式：使用适配器隔离协议、锁定兼容版本、建立自动兼容测试，不让移动端直接依赖 Codex 原始协议。

### 用户不信任远程授权

应对方式：开源主机端 Agent、端到端加密、一次性授权、明确风险解释、默认不提供永久授权。

### 产品变成日志查看器

应对方式：核心页面围绕“现在是否需要我做决定”，而不是围绕原始输出构建。

## 十一、商业化方向

推荐采用开源核心加托管服务的模式：

- 个人自托管版：免费
- 托管版：多设备、可靠推送、加密同步和历史记录
- 专业版：多主机、策略模板、资源监控
- 团队版：成员权限、审批委托、审计和私有化部署

主机 Agent 和事件协议可以开源，以建立安全信任；可靠中继、团队治理和企业运维作为商业能力。

---

## 十二、对外介绍文案

### 离开电脑，任务继续。

Steerloop 将运行在电脑和服务器上的 AI 编程任务安全连接到手机。

随时查看进度，及时回答问题，审批敏感操作，审阅修改结果。代码仍在你的机器上运行，Steerloop 不提供远程 Shell，也不要求把项目上传到云端。

当任务可以自己推进时，它保持安静；只有真正需要你时，才会提醒你。

> **Steerloop——让长时间运行的 AI 任务不再因为你离开电脑而停下来。**

---

## 十三、建议的下一步

最建议的下一步不是立即开发完整应用，而是先完成“Codex App Server → 主机 Agent → 手机审批页面”这一条最小链路。

只要这条链路能够安全、稳定地完成一次真实审批，整个产品方向就具备继续推进的基础。
